# З11. SQL и карточка — одно число

Метрика: **выручка сети** = `SUM(line_total)` по `fact_receipt_line` (эталон `P04/sql/canonical_metric.sql`).  
Число A — запрос из `sql/z11_check.sql` в `clickhouse-client`, число B — дашборд из P10.

```bash
docker exec -i olap_clickhouse clickhouse-client --multiquery < P11/sql/z11_check.sql
```

## Протокол

| № | Условия | A: SQL (ClickHouse) | B: дашборд (Metabase) | Вывод |
|---|---------|--------------------:|----------------------:|-------|
| 1 | весь 2024 год, все магазины, фильтр «Период» пуст | 15 383 068.36 | 15 383 068.36 (карточка «Выручка сети») | совпало |
| 2 | «Период» = 01.03.2024–31.03.2024, все магазины | 1 301 424.98 | 1 301 424.98 (карточка «Выручка сети») | совпало |
| 3 | «Период» = 01.03.2024–31.03.2024, магазин №1 (Москва) | 117 764.29 | 117 764.29 (столбец «Магазин №1» на графике «Выручка по магазинам») | совпало |

В строке 3 график читает сводку `sales_by_shop_day`, а SQL — детальный факт, значит сводка из P09 считает ту же формулу.

## Почему расхождений нет

- скрытых фильтров на карточках нет, единственный фильтр — «Период», он пуст в строке 1;
- карточка 1 смотрит в ту же таблицу `olap.fact_receipt_line` и тем же `sum(line_total)`, что эталон;
- деньги хранятся в `Decimal(12,2)` (P07), не во `FLOAT`, поэтому погрешности округления нет;
- формула метрики живёт в SQL-файлах (`P04/sql/canonical_metric.sql`, `P10/dashboards/widget1_revenue.sql`), подпись карточки её только называет.

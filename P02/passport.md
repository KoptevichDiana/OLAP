## 1. Бизнес-цель витрины

Витрина показывает весь путь товара в сети магазинов: **поставка → продажа → утилизация**.
Она отвечает на вопросы: что и где продаётся лучше, откуда и как быстро привозят товар, сколько денег теряем на испорченных продуктах и по какой причине.

---

## 2. Grain

| Процесс | Одна строка факта = |
|---------|---------------------|
| Продажа | одна строка чека (один товар, проданный одному клиенту в одном магазине в один момент) |
| Поставка | одна партия одного товара, привезённая одним поставщиком в один магазин |
| Утилизация | одно списание товара из одной партии в одном магазине |

---

## 3. Fact-таблицы

| Имя | Grain | Источник | Строк | Примечание |
|-----|-------|----------|-------|------------|
| `fact_receipt_line` | строка чека, ключ `receipt_line_id` | `fact_receipt.csv` | 25 000 | Номера чека в сырье нет, поэтому «средний чек» не посчитать — считаем по строкам. |
| `fact_supply` | партия, ключ `supply_id` | `fact_supply.csv` | 25 000 | Есть время отгрузки и привоза → считаем время доставки. `expiry_date` = «годен до» для партии. |
| `fact_writeoff` | списание, ключ `writeoff_id` | `fact_writeoff.csv` | 3 002 | Ссылается на партию `supply_id` — видно, из какой поставки выбросили товар. |

Все три факта используют **общие измерения** (товар, магазин, календарь), поэтому их можно сравнивать между собой: например, сколько товара привезли, продали и выбросили в одном магазине за месяц.

## 4. Меры

### fact_receipt_line — продажи

| Мера | Тип (sum ok / нет) | Определение |
|------|--------------------|-------------|
| `line_total` | sum ok | Выручка строки = `qty * sell_price`. |
| `qty` | sum ok только внутри одной единицы | Штуки или килограммы (см. `dim_goods.measure_unit`) — складывать вместе нельзя. |
| `sell_price` | sum нет | Цена за единицу; считаем среднюю, min/max. |
| `lines_cnt` | sum ok (count) | `COUNT(*)` — число строк чека. |

### fact_supply — поставки

| Мера | Тип (sum ok / нет) | Определение |
|------|--------------------|-------------|
| `supply_amount` | sum ok | Стоимость партии по закупочной цене = `qty * purchase_price`. |
| `qty` | sum ok только внутри одной единицы | Сколько привезли (шт / кг). |
| `purchase_price` | sum нет | Закупочная цена за единицу. |
| `delivery_hours` | sum нет (среднее) | Время в пути = `delivered_at - shipped_at`, в часах. |
| `supplies_cnt` | sum ok (count) | `COUNT(*)` — число партий. |

### fact_writeoff — утилизация

| Мера | Тип (sum ok / нет) | Определение |
|------|--------------------|-------------|
| `cost_amount` | sum ok | Потери = `qty * purchase_price` партии. |
| `qty` | sum ok только внутри одной единицы | Сколько выбросили (шт / кг). |
| `writeoffs_cnt` | sum ok (count) | `COUNT(*)` — число списаний. |
| `writeoff_rate` | sum нет (доля) | Доля потерь = `SUM(cost_amount) / SUM(supply_amount)`; считается заново на каждом разрезе. |

## 6. Три бизнес-вопроса

1. **Продажи:** какой отдел дал наибольшую выручку в каждом квартале 2024 года?
2. **Утилизация:** в каких отделах больше всего теряем на утилизации, по каким причинам и какая это доля от закупки?
3. **Поставки:** сколько в среднем едет товар от поставщика до магазина на каждом виде транспорта и какая часть закупки везётся в холодильнике?

## 7. Эталонный SQL главной метрики (черновик → уточнить на P04)

**Главная метрика: выручка сети** = `SUM(line_total)` по `fact_receipt_line`.
Возвратов в сырье нет, поэтому выручка = сумма всех продаж.

```sql
SELECT SUM(line_total) AS revenue
FROM fact_receipt_line;
```

Ожидаемое значение: **15 383 068.36**.

**Вспомогательная метрика: доля утилизации от закупки.**

```sql
SELECT
    (SELECT SUM(cost_amount)   FROM fact_writeoff) AS writeoff_cost,
    (SELECT SUM(supply_amount) FROM fact_supply)   AS supply_cost,
    ROUND(100.0 * (SELECT SUM(cost_amount) FROM fact_writeoff)
                / (SELECT SUM(supply_amount) FROM fact_supply), 2) AS writeoff_rate_pct;
```

Ожидаемое значение: **425 223.01 / 12 542 717.29 = 3.39 %**.

## 8. Риски / cut

- **Нет номера чека** — есть только `receipt_line_id`, настоящий «средний чек» не посчитать.
- **Штуки и кг в одном поле `qty`** — суммировать можно только по одной единице измерения.
- **Цена только текущая** — `list_price` без истории; для SCD2 нужны `valid_from` / `valid_to`.
- **Возвратов от покупателей нет** — выручка = продажи.
- **Остатков на складе нет** — остаток можно только оценить: привезли − продали − списали.
- **Стоимости доставки нет** — логистику можно оценить только по времени и виду транспорта.
- **ClickHouse-кластер / Kafka / ML** — не делаем, подробности в `cut.md`.

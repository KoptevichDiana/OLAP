## Как запустить

```bash
cd P05
python etl/load_data.py            # загрузка из data/raw
python etl/load_data.py            # второй прогон — проверяем, что факт не удвоился
python etl/load_data.py data/bad   # плохие данные — загрузка должна остановиться
```

## Цепочка

1. CSV читаются как есть (текстом) в промежуточные таблицы `stg_goods`, `stg_client`, `stg_receipt`.
2. На них запускаются проверки. Если хоть одна не прошла — скрипт пишет `СТОП` и выходит, **витрина не трогается**.
3. Очистка витрины: сначала `fact_receipt_line`, потом справочники.
4. Заполнение: **сначала справочники** (`dim_goods`, `dim_client`, `dim_shop`, `dim_pay_method`, `dim_calendar`), **потом факт**.
5. Сверка: число строк и `SUM(line_total)` в факте должны совпасть с CSV.

## Проверки качества

| Проверка | Что проверяем |
|----------|---------------|
| пустые ключи и суммы | в факте не пустые `receipt_line_id`, `sold_at`, `client_id`, `sku_id`, `shop_id`, `pay_method`, `qty`, `line_total`; в справочниках — ключи |
| странный диапазон | `qty`, `sell_price`, `line_total` ≥ 0; дата продажи из 2024 года (календарь только на 2024) |
| дубли | `receipt_line_id` уникален в факте, `sku_id` и `client_id` уникальны в справочниках |
| сироты | у каждой строки факта есть товар, клиент и магазин (1–12) в справочниках |

`dim_shop` теперь создаётся как справочник магазинов 1–12, а не из факта, — так проверка «сирот» по магазинам имеет смысл.

## Повторный запуск

**Что чистим при повторе:** перед заливкой полностью очищаем все таблицы витрины (сначала факт, потом справочники) и заполняем их заново из CSV.

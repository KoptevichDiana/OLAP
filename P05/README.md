## Связь с P03 и P04

P05 использует ту же модель данных, что и P03: **3 факта и 8 измерений**. Восстановлены все 10 исходных CSV из P03, включая расширенные поля товаров, поставки, списания, транспорт, поставщиков и причины списания.

Главная метрика соответствует эталону P04: `SUM(fact_receipt_line.line_total)`. Ожидаемое значение — **15 383 068.36**. Дополнительные контрольные суммы: закупка — **12 542 717.29**, списания — **425 223.01**.

## Как запустить

Из корневой папки `P05`:

```bash
python -m pip install duckdb
python etl/load_data.py
python etl/load_data.py
python etl/load_data.py data/bad
```

Первые два запуска — штатная загрузка. Третий — демонстрация остановки на плохих данных. Скрипт дописывает результаты запусков в `run_log.txt`.

## Цепочка ELT

1. Все 10 CSV загружаются во временные таблицы `stg_*` как текст.
2. Выполняются проверки качества. При любой ошибке загрузка останавливается до изменения витрины.
3. В транзакции выполняется пересоздание таблиц по DDL.
4. Сначала загружаются справочники: поставщики, товары, клиенты, магазины, календарь, способы оплаты, транспорт и причины списания.
5. Затем загружаются факты: продажи, поставки и списания.
6. Сверяются количество строк и суммы по каждому факту с исходными CSV. При несовпадении транзакция откатывается.

## Проверки качества

| Проверка | Что проверяется |
|---|---|
| пустые значения | обязательные поля фактов и ключи справочников |
| диапазоны | количества и суммы неотрицательные |
| даты | даты корректно разбираются и не начинаются с 1900 года |
| дубли | уникальность первичных ключей фактов и справочников |
| «сироты» | все товары, клиенты, магазины, поставщики, транспорт, причины и партии существуют |
| календарь | даты продаж, привоза и списания есть в `dim_calendar` |
| согласованность списания | товар и магазин совпадают с партией; списание не раньше привоза |

## Повторный запуск

**Что очищается при повторе:** все таблицы витрины пересоздаются внутри одной транзакции, после чего данные загружаются заново из CSV. Поэтому второй запуск не добавляет строки к первому и не удваивает суммы. Если загрузка завершается ошибкой, транзакция откатывается.

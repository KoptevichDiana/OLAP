# З09. Сводная таблица под график

## График

Виджет на З10: «Выручка по дням» (линия) и «Выручка по магазинам» (столбцы), оба с фильтром «Период».

**Одна строка сводки = один день + один магазин.**  
Для сравнения: одна строка факта `fact_receipt_line` = одна строка чека.

Таблица `olap.sales_by_shop_day`:

| Поле | Смысл |
|------|-------|
| `sale_date` | день продажи (`toDate(sold_at)`) |
| `shop_id`, `shop_name`, `city` | магазин |
| `revenue` | выручка за день в магазине = `sum(line_total)` |
| `lines_cnt` | число строк чека за день в магазине |

Метрика та же, что в эталоне `P04/sql/canonical_metric.sql`: `SUM(line_total)`, возвратов в сырье нет. Деньги — `Decimal`, как в факте.

25 000 строк факта → 4 369 строк сводки (366 дней × 12 магазинов, не каждый магазин продаёт каждый день).

## Файлы

- `sql/summary_ddl.sql` — создание таблицы (`MergeTree`, `ORDER BY (sale_date, shop_id)`);
- `sql/summary_fill.sql` — заполнение `TRUNCATE` + `INSERT … SELECT` из факта и `dim_shop`;
- `sql/check_summary.sql` — сверка с детальной таблицей.

Запуск (из корня репозитория, после `P07/etl/load_all.py`):

```bash
docker exec -i olap_clickhouse clickhouse-client --multiquery < P09/sql/summary_ddl.sql
docker exec -i olap_clickhouse clickhouse-client --multiquery < P09/sql/summary_fill.sql
docker exec -i olap_clickhouse clickhouse-client --multiquery --format TabSeparatedWithNames < P09/sql/check_summary.sql > P09/notes/check_output.txt
```

## Сверка сводки с детальной таблицей

| Условие | `fact_receipt_line` | `sales_by_shop_day` |
|---------|--------------------:|--------------------:|
| весь 2024 год, все магазины | 15 383 068.36 | 15 383 068.36 |
| строк чека, весь год | 25 000 | 25 000 (`sum(lines_cnt)`) |
| март 2024, все магазины | 1 301 424.98 | 1 301 424.98 |
| март 2024, магазин №1 (Москва) | 117 764.29 | 117 764.29 |

Суммы совпадают до копейки, вывод запросов — `check_output.txt`.  
Эталон метрики по-прежнему считается по детальной таблице `fact_receipt_line`, сводка нужна только графикам.

## Как пересчитать после повторной загрузки

После каждого `python3 P07/etl/load_all.py` сводка пересобирается целиком скриптом `sql/summary_fill.sql` (`TRUNCATE` + `INSERT … SELECT`), так же как P07 перезаливает факты. На 25 000 строк это доли секунды, поэтому полный пересчёт проще инкрементального и не даёт дублей.
